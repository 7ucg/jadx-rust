## [Unreleased]

### Added
- `jadx-input-api` with the jadx-normalised 155-value `Opcode` enum, `InsnData` and switch/array payloads (generated by `tools/gen_opcode_map.py` from the reference sources); `jadx-dex-input` converts Dalvik instructions to `InsnData` (absolute branch targets, expanded range registers, unknown opcodes kept as `Unknown`). Verification: instruction streams identical to the reference input plugin on 6 inputs, 645,777 methods and 15,761,814 instructions (`tests/oracle/insns_oracle.sh`).
- `jadx-core`: type model (`ArgType`), class/field/method descriptors, instruction nodes, instruction decoder and the instruction post-processing pass (work in progress, oracle: `tests/oracle/nodes_oracle.sh`).
- `jadx-core`: generic signature parser and processor, class hierarchy graph with the bundled framework class set, type comparison, generic type variable mapping, override based return/argument type fixes. Verification: decoded instruction nodes identical to the reference on 371,908/371,908 methods of a large app and 108,147/108,194 of a second one (`tests/oracle/nodes_oracle.sh`; the remaining differences are class names with nested `$` synthetic parts).
- `jadx-core`: try/catch attachment and basic block splitting (blocks, edges, exception handler edges, exit connections). Verification: block graphs identical to the reference on 371,908/371,908 methods (`tests/oracle/blocks_oracle.sh`).
- `jadx-core`: dominator tree, dominance frontier, post dominators, loop detection and the CFG normalisation of the block processor for methods without exception handlers (loop pre-headers/exits, const-return merging, return/throw splitting, multi-entry loop fixes). Verification: block graphs with dominator/loop data identical to the reference on all methods without exception handlers of a 108k method app (`STAGE=1 tests/oracle/blocks_oracle.sh`).
- `jadx-core`: exception handler processing of the block graph (handler blocks, try/catch block structure, top/bottom splitters, multi-catch merging, handler ordering) with emulation of the reference's hash map and sort orders. Verification: block graphs incl. dominators, loops and try blocks identical to the reference on 108,144/108,194 methods of one app and 371,872/371,908 of a large one (`STAGE=1 tests/oracle/blocks_oracle.sh`); remaining differences are class names with nested synthetic parts and 39 methods with many handlers.
- `jadx-core`: SSA construction (live variable analysis, phi placement on the dominance frontier, variable renaming over the dominator tree, try/catch phi fixes, useless-phi elimination, `this` marking, unused invoke result removal) on the per-method instruction arena, with phi instructions and SSA variable/use tracking. Verification: SSA variables, phis and register versions identical to the reference on 108,144/108,194 methods of a large app and all corpus methods (`STAGE=2 tests/oracle/blocks_oracle.sh`; the remaining differences are the nested-class-name cases and many-handler try blocks listed above).
- `jadx-core`: move instruction inlining and constructor call replacement (`invoke <init>` → constructor instructions incl. new-instance chain removal, synthetic constructor redirection and phi insertion for shared instances). Verification: SSA variables with use lists, phis and 43,783 constructor instructions identical to the reference on 108,140/108,194 methods of a large app (`STAGE=4 tests/oracle/blocks_oracle.sh`); the other differences are the previously listed ones plus 3 methods where the reference shares one register argument object between several instructions.
- `jadx-core`: code variable initialisation, constant inlining with wrapped instruction arguments, generic type variable expansion for method frames, and type inference from bounds (type bounds, candidate type propagation through moves, phis, arrays, casts, invokes). Class passes now run in the reference order (sorted by raw name); override base method data and bridge collisions are kept per method. Verification: SSA variables, uses, code variables, types and bounds identical to the reference on 108,142/108,194 methods of a large app (`STAGE=7 tests/oracle/blocks_oracle.sh`).
- `jadx-core`: instruction modification (`ModVisitor`: filled array merge, check-cast removal and duplicate merge, boolean cast to ternary, compare inlining into `if`, field access casts, move-exception handling, unused instruction removal) and variable inlining (`CodeShrinkVisitor`: single use variable inlining within and across blocks, `move` simplification), with named arguments, ternary instructions and argument flags added to the instruction model. Constant field replacement and anonymous class constructor handling are not ported yet. Verification: SSA variables, uses, wrapped instruction trees, flags and code variables identical to the reference (run without the type fixing passes) on 108,141/108,194 methods after the modification pass and 108,140/108,194 after the shrink pass of a large app (`STAGE=10` / `STAGE=11 tests/oracle/blocks_oracle.sh`); the 2 methods beyond the earlier differences are again the shared register argument objects of the reference.
- `jadx-rs insn-dump`, `insn-nodes`, `insn-blocks`, `insn-cfg` and `insn-ssa` developer subcommands.

## 2026-11-12 — Smali output
### Added
- Dalvik opcode table (227 entries) generated from the reference dexlib2 table, and a decoder for every instruction format incl. switch/array payloads.
- `class_data_item`, `code_item` (tries, catch handlers), annotations and encoded values parsing in `jadx-dex-input`.
- Smali emitter (`DexFile::class_smali`) reproducing the reference disassembler output without debug info: labels, `.catch`, payload blocks, `p` registers, annotations, static initial values, float/double literal comments, Java-compatible `Float/Double.toString`.
- `jadx-rs smali` and `jadx-rs dex-opcodes` developer subcommands.
- Oracle harness: `tests/oracle/smali_oracle.sh` (smali diff per class and per method), `tests/oracle/corpus_oracle.sh` + hand-written corpus (`tests/oracle/corpus/*.smali`, assembled by the reference assembler) covering the 11 opcodes absent from real APKs, regression test against committed reference output, fuzz test (30k corrupted inputs, no panics).
- Verification: oracle parity 100% — 250,274/250,274 classes and 1,093,874/1,093,874 methods identical over 8 inputs (3 samples, 5 real-world APKs up to 104,904 classes) plus the 2-class corpus. Opcode coverage 227/227. jadx-rs processes an 18.8k-class APK in about 1 s.

## 2026-11-12 — DEX parsing
### Added
- Cargo workspace (`jadx-core`, `jadx-api`, `jadx-input-api`, `jadx-dex-input`, `jadx-java-input`, `jadx-cli`, `jadx-mcp`).
- `jadx-dex-input`: DEX header, map list, id tables, class definitions, type lists, MUTF-8 strings, Adler-32 verification, v41 container splitting, loading from `.dex`/`.apk`/`.jar`/`.zip` — table counts and class list (type, flags, super, interfaces) identical to the Java reference reader on 7/7 inputs (145,368 classes).
- `jadx-rs` developer subcommands `dex-info`, `dex-classes`, `dex-map`, `dex-counts`.
- Oracle harness `tests/oracle/classes_oracle.sh` + `tests/oracle/java/DexClassDump.java`.
- Robustness tests: every truncation of a synthetic DEX and 20,000 random byte corruptions return errors instead of panicking.
