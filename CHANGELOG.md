# Changelog — jadx-rs

All notable changes to the Rust rewrite are recorded here.
Format: [Keep a Changelog](https://keepachangelog.com/). Every correctness-affecting entry
cites its verification (oracle parity, benchmark, or test result).

## [Unreleased]

### Added
- `jadx-index`: cross reference index over the `jadx-core` root and decoded instructions: callers (resolved to the declaring method through the class hierarchy), callees, field readers and writers, string and integer literal sites, class uses by type operands, a bounded call graph with component classification, name search (exact, prefix, substring, glob, camel case, word) with a package scope filter, and a posting store that stays in memory or spills to disk beyond a memory budget. Verification: the callers of every method equal the `use_in` lists of the core usage pass on 391,626/391,626 methods of a large app (6.55 million sites, built in 1.2 s, identical with the disk backed store) and on 114,782/114,853 methods of a second app (the differences are bridge methods that differ only by return type); unit tests in the crate (`jadx-rs xref <file> check-usage`).
- `jadx-package`: package containers (`.xapk`, `.apks`, `.apkm`, plain APK) with split-aware logical entry paths (`splits/<name>/...`, `container/...`), bundletool `toc.pb` variant selection and split identity validation in strict mode, and multi-source input loading that matches the reference input plugins (dex files anywhere in an archive including `assets/`, JVM classes from archives nested at any depth, the APKs of split packages, duplicate class selection of the reference root). Verification: class name and source list identical to the reference (all input plugins) on 2/2 real APKs (18,844 and 28,971 classes) and on 4 synthetic split containers built from them (`tests/oracle/input_oracle.sh`).
- `jadx-input-api` with the jadx-normalised 155-value `Opcode` enum, `InsnData` and switch/array payloads (generated by `tools/gen_opcode_map.py` from the reference sources); `jadx-dex-input` converts Dalvik instructions to `InsnData` (absolute branch targets, expanded range registers, unknown opcodes kept as `Unknown`). Verification: instruction streams identical to the reference input plugin on 6 inputs, 645,777 methods and 15,761,814 instructions (`tests/oracle/insns_oracle.sh`).
- `jadx-core`: type model (`ArgType`), class/field/method descriptors, instruction nodes, instruction decoder and the instruction post-processing pass (work in progress, oracle: `tests/oracle/nodes_oracle.sh`).
- `jadx-core`: generic signature parser and processor, class hierarchy graph with the bundled framework class set, type comparison, generic type variable mapping, override based return/argument type fixes. Verification: decoded instruction nodes identical to the reference on 371,908/371,908 methods of a large app and 108,147/108,194 of a second one (`tests/oracle/nodes_oracle.sh`; the remaining differences are class names with nested `$` synthetic parts).
- `jadx-core`: try/catch attachment and basic block splitting (blocks, edges, exception handler edges, exit connections). Verification: block graphs identical to the reference on 371,908/371,908 methods (`tests/oracle/blocks_oracle.sh`).
- `jadx-core`: dominator tree, dominance frontier, post dominators, loop detection and the CFG normalisation of the block processor for methods without exception handlers (loop pre-headers/exits, const-return merging, return/throw splitting, multi-entry loop fixes). Verification: block graphs with dominator/loop data identical to the reference on all methods without exception handlers of a 108k method app (`STAGE=1 tests/oracle/blocks_oracle.sh`).
- `jadx-core`: exception handler processing of the block graph (handler blocks, try/catch block structure, top/bottom splitters, multi-catch merging, handler ordering) with emulation of the reference's hash map and sort orders. Verification: block graphs incl. dominators, loops and try blocks identical to the reference on 108,144/108,194 methods of one app and 371,872/371,908 of a large one (`STAGE=1 tests/oracle/blocks_oracle.sh`); remaining differences are class names with nested synthetic parts and 39 methods with many handlers.
- `jadx-core`: SSA construction (live variable analysis, phi placement on the dominance frontier, variable renaming over the dominator tree, try/catch phi fixes, useless-phi elimination, `this` marking, unused invoke result removal) on the per-method instruction arena, with phi instructions and SSA variable/use tracking. Verification: SSA variables, phis and register versions identical to the reference on 108,144/108,194 methods of a large app and all corpus methods (`STAGE=2 tests/oracle/blocks_oracle.sh`; the remaining differences are the nested-class-name cases and many-handler try blocks listed above).
- `jadx-core`: move instruction inlining and constructor call replacement (`invoke <init>` → constructor instructions incl. new-instance chain removal, synthetic constructor redirection and phi insertion for shared instances). Verification: SSA variables with use lists, phis and 43,783 constructor instructions identical to the reference on 108,140/108,194 methods of a large app (`STAGE=4 tests/oracle/blocks_oracle.sh`); the other differences are the previously listed ones plus 3 methods where the reference shares one register argument object between several instructions.
- `jadx-core`: code variable initialisation, constant inlining with wrapped instruction arguments, generic type variable expansion for method frames, and type inference from bounds (type bounds, candidate type propagation through moves, phis, arrays, casts, invokes). Class passes now run in the reference order (sorted by raw name); override base method data and bridge collisions are kept per method. Verification: SSA variables, uses, code variables, types and bounds identical to the reference on 108,142/108,194 methods of a large app (`STAGE=7 tests/oracle/blocks_oracle.sh`).
- `jadx-core`: instruction modification (`ModVisitor`: filled array merge, check-cast removal and duplicate merge, boolean cast to ternary, compare inlining into `if`, field access casts, move-exception handling, unused instruction removal) and variable inlining (`CodeShrinkVisitor`: single use variable inlining within and across blocks, `move` simplification), with named arguments, ternary instructions and argument flags added to the instruction model. Constant field replacement and anonymous class constructor handling are not ported yet. Verification: SSA variables, uses, wrapped instruction trees, flags and code variables identical to the reference (run without the type fixing passes) on 108,141/108,194 methods after the modification pass and 108,140/108,194 after the shrink pass of a large app (`STAGE=10` / `STAGE=11 tests/oracle/blocks_oracle.sh`); the 2 methods beyond the earlier differences are again the shared register argument objects of the reference.
- `jadx-core`: class level pre decompile passes run from `passes::pre_decompile::run_pre_decompile` in the reference order: class access flags from the `InnerClass` annotation (restoring `static` of member classes), android resource constants, usage info (`useIn`, used/unresolved methods, class dependencies), collection of static final constants into `ConstStorage` (`getConstField`, `getConstFieldByLiteralArg`), anonymous class marking (`AnonymousClassAttr`, anonymous constructors, instance field inlining, codegen dependencies) and inline candidates. `jadx-input-api`/`jadx-dex-input` now provide inner class data, annotation references, static field constants and per-method code references. Verification: access flags, anonymous marks, dependency lists, use lists and const storage identical to the reference on 4 inputs (the corpus and three real apps; 1,312,522 class/field/method records) with `tests/oracle/pre_oracle.sh`. Not ported: resource table based fields (the reference adds resource id fields to the app `R` class), non-default pass options on the command line.
- `jadx-core`: finally block extraction (`passes::mark_finally`): try edge and execution scope groups, per-edge block scopes, a backwards comparison of the catch-all handler against every other exit of the try (shared mutable traversal state, path merging, cached block pair results), marking of duplicated instructions (`DONT_GENERATE`) and finally code (`FINALLY_INSNS`), hiding of the rethrow, removal of implicit catch-all handlers and merging of inner try blocks. Runs after code variable initialisation when `build_ssa` is called with `extract_finally` (`JADX_RS_FINALLY=1` for `insn-ssa`). Verification: with the reference run in the same mode, 108,141/108,194 methods of a large app are identical, including all 442 finally handlers and 1,352 finally instruction flags (`STAGE=6 JADX_RS_FINALLY=1 tests/oracle/blocks_oracle.sh`); the remaining differences are the ones already listed. The reference iterates hash maps keyed by try edges (identity hash code of an enum), so its result is only reproducible with a constant identity hash, which the oracle script sets in this mode and the port emulates. A finally fixture was added to the corpus (`tests/oracle/corpus/Finally.smali`).
- `jadx-core`: type fixing (multi-variable type search, field type casts, type variable cast restoration, cast insertion, constant instruction splitting, boolean usage conversion, additional moves before phis, raw types) and the final type check, with the reference's hash set iteration order for super types and implementations. Verification: SSA variables, types, bounds and code variables identical to the reference on 106,865/108,194 methods of a large app after type fixing and 106,866/108,194 after the final check (`STAGE=8` / `STAGE=9 tests/oracle/blocks_oracle.sh`); no method differs that was identical before type fixing, the remaining differences come from the earlier stages (4,617 of the 4,838 methods changed by type fixing match exactly).
- `jadx-core`: constant field replacement through the constant storage in `ConstInlineVisitor` and `ModVisitor` (literals, strings, switch keys, arithmetic operands, filled array elements; used fields are recorded per method in `MethodCfg::field_uses`), anonymous constructor argument handling (arguments marked `DONT_INLINE`, variables made final) and constant array size lookup through constant fields. Verification: stages 6, 9, 10 and 11 of a large app without resource table identical to the reference on 108,142 / 108,143 / 108,143 / 108,142 of 108,194 methods (`tests/oracle/blocks_oracle.sh`); the remaining differences are the previously listed ones. The resource table is not parsed, so resource id constants of the app `R` class are not replaced (18 further methods on the original app).
- `jadx-mcp`: Model Context Protocol server (`jadx-mcp` binary and `jadx-rs mcp`) over stdio or a Unix domain socket, with 28 tools: project loading (apk, xapk, dex, jar, class), class and package listing and search, class/method source (declaration skeleton until the code generator exists, behind the `Project` trait), smali, manifest summary and resource access, DEX strings and string references, member search, hierarchy and usage queries from the pre decompile usage information, paging with source hashes and request cancellation. Parts of the transport, tool registry and tool conventions are adapted from RDX (Apache-2.0), see NOTICE. Verification: unit tests and an end to end test suite over the oracle corpus, a synthetic apk and xapk, the stdio binary and a local socket (`cargo test -p jadx-mcp`).
- `jadx-core::codegen`: instruction and expression level code generation: `InsnGen` (all instruction kinds incl. operator precedence brackets, casts, static/virtual/super/direct/polymorphic invokes, constructors incl. outer instance and `this`/`super` calls, field and array access, filled arrays, array fill, string concatenation, ternaries with their float/boolean compare conditions, wrapped instruction trees), `TypeGen` (signatures, literal formatting incl. Java `Float`/`Double.toString`, char/string escapes with the reference's printable code point table), `NameGen` (unique variable names, fallback register names), `ApplyVariableNames` (`codegen::var_names`), `ClassGen` type and class name helpers (import bookkeeping, short/full name decision, inner class expansion, collision checks) and a code writer with line bookkeeping. Anonymous class bodies, lambdas (`invoke-custom`) and fallback mode are not generated.
- `jadx-core::passes::rename`: the renaming pass of the reference (invalid, non printable and colliding class, field, method and package names, `AnonymousClass<N>`, `C<N>` names, `m<N>`/`mo<N>` methods with the shared override hierarchy, `defpackage`, case insensitive file system conflicts) with its alias provider counters; `OverrideMethodVisitor` now keeps the related method sets and renames colliding methods after type fixes. Output names are available through `Root::class_full_name`, `field_name`, `method_name` and `package_name`.
- Verification (`tests/oracle/codegen_oracle.sh`, reference run up to the shrink pass, code string per block instruction and per wrapped instruction): 1,079,300/1,081,595 (99.79%) identical on a 108k method app and 86/86 on the corpus; with variables declared at their first assignment and named by `ApplyVariableNames` (`NAMES=1`) 1,079,294/1,081,595. The remaining differences are the resource id constants of the app `R` class (the resource table is not parsed), one method with a different block structure and one variable name taken from another SSA variable of a merged code variable.
- `jadx-rs insn-code` developer subcommand (code string per instruction, oracle comparison format).
- `jadx-rs insn-dump`, `insn-nodes`, `insn-blocks`, `insn-cfg` and `insn-ssa` developer subcommands (`pre-info` prints the class level state after the pre decompile passes).

## 2026-11-12 — Smali output
### Added
- Dalvik opcode table (227 entries) generated from the reference dexlib2 table, and a decoder for every instruction format incl. switch/array payloads.
- `class_data_item`, `code_item` (tries, catch handlers), annotations and encoded values parsing in `jadx-dex-input`.
- Smali emitter (`DexFile::class_smali`) reproducing the reference disassembler output without debug info: labels, `.catch`, payload blocks, `p` registers, annotations, static initial values, float/double literal comments, Java-compatible `Float/Double.toString`.
- `jadx-rs smali` and `jadx-rs dex-opcodes` developer subcommands.
- Oracle harness: `tests/oracle/smali_oracle.sh` (smali diff per class and per method), `tests/oracle/corpus_oracle.sh` + hand-written corpus (`tests/oracle/corpus/*.smali`, assembled by the reference assembler) covering the 11 opcodes absent from real APKs, regression test against committed reference output, fuzz test (30k corrupted inputs, no panics).
- Verification: oracle parity 100% — 250,274/250,274 classes and 1,093,874/1,093,874 methods identical over 8 inputs (3 samples, 5 real-world APKs up to 104,904 classes) plus the 2-class corpus. Opcode coverage 227/227. jadx-rs processes an 18.8k-class APK in about 1 s.

## 2026-11-12 — DEX parsing
### Added
- Cargo workspace (`jadx-core`, `jadx-api`, `jadx-input-api`, `jadx-dex-input`, `jadx-java-input`, `jadx-cli`, `jadx-mcp`).
- `jadx-dex-input`: DEX header, map list, id tables, class definitions, type lists, MUTF-8 strings, Adler-32 verification, v41 container splitting, loading from `.dex`/`.apk`/`.jar`/`.zip` — table counts and class list (type, flags, super, interfaces) identical to the Java reference reader on 7/7 inputs (145,368 classes).
- `jadx-rs` developer subcommands `dex-info`, `dex-classes`, `dex-map`, `dex-counts`.
- Oracle harness `tests/oracle/classes_oracle.sh` + `tests/oracle/java/DexClassDump.java`.
- Robustness tests: every truncation of a synthetic DEX and 20,000 random byte corruptions return errors instead of panicking.
